# 智能应用预审打分系统

面向应用竞赛预审场景的智能打分工具：录入申报信息并与大模型联动，抓取应用链接、OpenLab 文章、开源代码仓的真实内容作为评审依据，输出多维加权评分，支持单个评分、批量评分与评分历史。

## 功能特性

- **大模型评审**：基于抓取到的真实内容逐条打分，理由引用来源，避免臆测；并按赛题注入专属评分标准（任务目标、基础指标、加分指标、各维度评分要点），同一维度在不同赛题下侧重不同。
- **多维加权评分**：5 个维度各满分 100，按权重加权为「五维加权分」（满分 100）。
- **加分项**：开源加分（+5，任意代码仓链接只要可公开访问即加分，不限 Git 平台）、定向揭榜赛题加分（+10，参选前三个赛题），综合总分满分 115。
- **批量评分**：上传表格模板，一键批量打分；支持全局横向校准，保证跨应用可比，结果可导出 CSV（「五维加权分」「综合总分」以 Excel 公式给出，可随维度分修改自动重算）。
- **代码仓可访问性检测**：自动探测代码仓，不可访问时标记为「私有」，并回退读取 README 原始内容。
- **评分历史**：单次与批量结果自动留存，完整保留各维度评分依据、综合评价与报错记录，支持查看、下载与删除。批量结果每行应用带 3 个输入链接，可逐行标记「晋级 / 待定 / 淘汰」（绿色 / 橙色 / 灰色标签，实时保存、可随时修改）；各维度分值（含「待评」维度）可就地修改，修改需显式确认（回车或 ✓ 保存、Esc 或 ✗ 取消），仅在分值实际发生变化时以红色字体（不加粗）标注，并自动重算五维加权分与综合总分；应用名称支持双击从 COSMO Code 应用链接重新获取；点「按赛题排序」按赛题分组展示，排序前自动对原始顺序做快照，可一键「恢复原始顺序」。
- **应用名称刷新**：批量评分预览列表与评分历史均支持双击应用名称，从 COSMO Code 应用链接重新抓取并回填名称。
- **导出**：保留原有 CSV 模板不变；另提供「下载排序」，按赛道分不同 sheet 导出 Excel，含评审结果并支持公式重算。
- **链接校验**：COSMO Code 应用链接格式无效、缺失或不可访问（如 HTTP 4xx/5xx）时直接计 0 分（disqualified）。

## 评分规则

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 创意度 | 20% | 创新性与差异化优势：技术思路、AI 能力运用与场景切入的新颖程度 |
| 完整度 | 25% | 功能与闭环完整度：核心功能是否完整可用、关键流程是否跑通闭环 |
| 场景价值 | 25% | 场景价值与落地性：是否解决真实痛点、指标达成与推广价值 |
| 设计打磨 | 10% | 交互与工程打磨：界面完成度、交互体验、可解释性呈现、细节处理 |
| COSMO Code 使用深度 | 20% | 对 COSMO Code 平台能力的使用深度（暂不自动评分，留待人工评分；导出表格该列带权重与公式，手工填写后自动重算） |

总分计算公式：

```
综合总分 = 五维加权分（满分 100）
         + 开源加分（+5，代码仓可公开访问即加分）
         + 定向揭榜赛题加分（+10，参选前三个赛题）
       = 满分 115
```

## 技术栈

- 前端：React 18 + Vite + TypeScript + Tailwind CSS v4
- 后端：Node.js + Express（同时托管前端构建产物，单服务单端口）
- 抓取：`fetch` + `puppeteer-core`（SPA 兜底）+ `xlsx`（表格解析与导出）

## 目录结构

```
.
├── server/                 # 后端服务（同时托管前端 dist）
│   ├── index.js            # 主服务：API 路由、评分流程、静态资源与 SPA 回退
│   ├── browser.js          # 无头浏览器渲染
│   ├── repo.js             # 代码仓抓取与可访问性探测
│   └── data/               # 历史数据持久化（gitignore）
├── src/                    # 前端
│   ├── api/                # 接口封装
│   ├── components/         # 组件（Button、ScoreResult、BatchScorer、HistoryPanel）
│   ├── config/             # 维度、赛题、赛道、版本记录
│   ├── utils/              # 校验、历史、评分、表格工具
│   ├── App.tsx             # 页面入口与页脚版本记录

├── dist/                   # 前端构建产物（由 Express 托管）
├── .env.example            # 环境变量示例
└── vite.config.ts          # Vite 配置（开发模式下 /api 反向代理）
```

## 快速开始

### 1. 安装依赖

```bash
npm install
```

### 2. 配置环境变量

复制 `.env.example` 为 `.env` 并按需填写；未配置大模型时后端进入演示模式。

```bash
cp .env.example .env
```

### 3. 启动服务

前端构建产物由后端（Express）统一托管，只跑一个服务、暴露一个端口（默认 3001）：

```bash
npm start
```

`npm start` 会先执行 `npm run build` 生成 `dist/`，再启动 Express 同时提供 API 与前端页面。访问根路径 `/` 即为首页。

一键脚本等价于上述流程：

```bash
bash start.sh
```

如需前端热更新调试，可单独运行 `npm run dev`（Vite，默认 5173，已将 `/api` 反向代理到后端 3001，需另行启动 `npm run server`）。

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `LLM_BASE_URL` | 大模型接口地址（OpenAI 兼容） |
| `LLM_API_KEY` | 大模型密钥 |
| `LLM_MODEL` | 模型名称 |
| `GITLAB_TOKEN` | GitLab / GitCode 令牌（可选） |
| `GITLAB_HOSTS` | 允许携带令牌的主机白名单，逗号分隔（可选） |
| `CHROMIUM_PATH` | 无头浏览器可执行文件路径 |
| `PORT` | 服务端口，默认 3001 |

## 可用脚本

| 命令 | 说明 |
| --- | --- |
| `npm start` | 构建前端并启动单服务（Express 托管前端 + API，默认 3001） |
| `npm run build` | 类型检查并构建生产包 |
| `npm run dev` | 启动前端开发服务器（Vite，热更新调试） |
| `npm run server` | 仅启动后端服务（不构建前端） |
| `npm run preview` | 预览构建产物 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `POST` | `/api/score` | 单个应用评分 |
| `POST` | `/api/calibrate` | 批量全局横向校准 |
| `POST` | `/api/check-repos` | 代码仓可访问性检测 |
| `GET` | `/api/history` | 读取评分历史 |
| `POST` | `/api/history` | 保存评分历史 |
| `DELETE` | `/api/history/:id` | 删除评分历史 |
| `PATCH` | `/api/history/:id/decision` | 更新批量记录中某行应用的评审状态（晋级 / 待定 / 淘汰） |
| `PATCH` | `/api/history/:id` | 更新历史记录（如按赛题排序状态与原始顺序快照） |

## 批量表格模板

在「批量评分」标签页下载表格模板，按列填写：应用名称（选填）、赛道、赛题、COSMO Code 应用链接、OpenLab 文章链接、开源代码仓。上传后系统会预览全部字段并校验链接格式，确认无误后一键批量打分。模板内含独立「填写示例」表，示例行会被自动跳过。
